# Внешние лингвистические источники: подключение и проверка

**Статус на 8 ноября 2026:** адаптеры реализованы в `scripts/linguistic-sources.cjs`. Это **контур импорта предложений**, не импорт в основной словарь и не готовый генератор предложений. Основной источник `outputs/library-v2.json` и все утверждённые слова/веса/картинки/отношения остаются неизменными.

## Запуск на компьютере разработчика (Node.js 22+)

Из корня приватного репозитория:

```sh
# Конструктикон: безопасные предложения конструкций, не меняет V2
node scripts/linguistic-sources.cjs --source constructicon --fetch

# FrameBank: только локальная исследовательская проверка; в репозиторий производные данные не добавлять
node scripts/linguistic-sources.cjs --source framebank --fetch --accept-gpl-review-only

# Wikidata: сначала подготовить проверенные соответствия ID значений ↔ QID (пример ниже)
node scripts/linguistic-sources.cjs --source wikidata --mapping .local/linguistic-sources/mappings.json --fetch
```

**Формат mappings.json** — массив с реальными ID из `outputs/library-v2.json`, например `[{"entry_id":"<ID конкретного значения>","qid":"Q12345"}]`. В примере QID — заглушка, не подтверждённое соответствие. Чтобы получить связи, как минимум два связываемых QID должны иметь однозначное сопоставление с нашими ID.

Локальные исходники сохраняются в `.cache/linguistic-sources/`, предложения — в `.local/linguistic-sources/<source>-suggestions.json`. Обе папки исключены из Git. При запуске без `--fetch` используются ранее загруженные исходники. Для Конструктикона и FrameBank загрузки привязаны к фиксированным Git-коммитам; исходные файлы снабжаются контрольными SHA-256 в отчёте.

## Формат предложений и границы автоматизации

- `source`, `source_record_id`, `license`, `source_revision` — происхождение; все записи `review_status: suggested`.
- `candidate_type: construction_anchor` — конструкция Конструктикона, привязанная к лемме **для проверки**, а не утверждённый тип глагольного фрейма.
- `candidate_type: valency_pattern` — слот FrameBank: форма, семантическая роль, семантический класс. **Класс FrameBank сам источник отмечает как не полностью проверенный**, автоматически не превращать его в принятый учебный факт.
- `candidate_type: semantic_relation` — структурированное отношение Wikidata между **двумя вручную сопоставленными** значениями. Только предложение, даже для `is_a`.
- `entry_id` заполняется при единственном совпадении леммы; `entry_candidates` сохраняет все возможные значения. При омонимии `entry_id: null`. Единственное совпадение леммы всё равно **не подтверждает точное значение** и остаётся `suggested`.
- `usable_for_generation: false` — внешний материал не разрешён для генерации детских предложений до валидации и утверждения. Подтверждение должно включать нормативную грамматику, типичную сочетаемость и звуковые ограничения готового предложения.
- Исходные данные проверяются только по собственным ID; сообщения с названием «мышь» не связывают животное и устройство.
- Удаление дублей внутри предложения не означает объединения разных значений или слияния самостоятельных моделей.

**Ни один импортёр не записывает в `outputs/library-v2.json`, `public/library.json` или реестр проверенных связей.** Проверка и утверждение отношений потребуют будущего интерфейса редактора с явным действием «принять / отклонить».

## Ограничения первого подключения

1. Конструктикон преимущественно описывает полуустойчивые конструкции, **не заменяет** базу типичных детских предметно-глагольных сочетаний.
2. FrameBank содержит именно полезную грамматическую валентность, но не разрешает безусловный коммерческий перенос; результаты нельзя выдавать за готовые проверенные схемы.
3. Wikidata предлагает сведения о понятиях, но их классы и русские названия не всегда совпадают с педагогическими значениями. Нужна проверенная таблица `entry_id ↔ QID` и редакторский отбор отношений.
4. Для цепочки «типичная ситуация → проверенный грамматический шаблон → 2–5 слов со звуками С/СЬ/З/ЗЬ/Ц без Р/РЬ» нужен **отдельный генератор** и проверка фонетики **всех полученных форм и предлогов**, не только лемм.
5. После проверки нужно добавить безопасную идемпотентную операцию принятия предложений с учётом уже существующих отношений, обратных ролей и источников; не включать этот этап в автоматический загрузчик.

## Проверки

`node --experimental-strip-types --test tests/linguistic-sources.test.ts` проверяет CSV с кавычками/переносами строк, неоднозначные написания, извлечение ролей FrameBank без копирования примеров, Wikidata с ручными QID и исключение дубликатов. Эти тесты не доказывают качества конкретной внешней конструкции или соответствия всем значениям словаря.


## 8 ноября: визуальная приёмка и автономная выгрузка

**Реализованы технические компоненты:**

- \`outputs/Проверка-смысловых-связей.html\` — локальный визуальный редактор предложенных **семантических** связей Wikidata; загружает основной JSON и файл предложений пользователя; показывает два значения с ID, источник и лицензию, требует подтверждения значения и педагогической типичности; позволяет принять, отклонить и скачать решения. Он не отправляет данные наружу и самостоятельно не перезаписывает мастер.
- \`scripts/semantic-review.cjs\` — проверяет решения по первоначальным предложениям, источнику CC0, точным ID, QID и типу связи. \`apply\` записывает только принятые связи непосредственно в **единственный** мастер \`outputs/library-v2.json\`, с журналом решений \`semantic_review_history\`. Ранее утверждённые родовые связи не дублируются; семейные связи сохраняются.
- \`scripts/export-library.cjs\` — вместе с игровым \`public/library.json\` создаёт статический \`public/semantic-graph.json\` из основного V2: существующие родовые и семейные отношения плюс проверенные новые. Никаких пакетов внешнего анализа для выполнения игры не требуется.
- \`tests/semantic-review.test.ts\` и \`.github/workflows/semantic-review-tests.yml\` — проверки допуска, отказа, лицензий, двойных связей и экспорта.

**Порядок редакторской работы** (Node.js 24+, из корня рабочего проекта):

1. Сформировать предложения Wikidata: \`node scripts/linguistic-sources.cjs --source wikidata --mapping .local/linguistic-sources/mappings.json --fetch\`. QID заранее вручную сопоставить с ID значений; сам импортёр их не угадывает.
2. Открыть \`outputs/Проверка-смысловых-связей.html\` локально в браузере. Указать \`outputs/library-v2.json\` и \`.local/linguistic-sources/wikidata-suggestions.json\`. Проверить предложения, скачать \`semantic-review-decisions.json\`.
3. Применить решения **только после просмотра файла**:
   \`\`\`sh
   node scripts/semantic-review.cjs apply outputs/library-v2.json .local/linguistic-sources/wikidata-suggestions.json semantic-review-decisions.json
   \`\`\`
   Выполнять в чистой рабочей ветке Git; проверить diff перед коммитом. При повторном применении одинаковые связи не дублируются. Отклонение ранее принятого предложения из того же источника отзывает соответствующую внешнюю связь, не трогая исходные редакторские связи.
4. Проверить библиотеку и пересобрать игровую выгрузку: \`node scripts/check-library-v2.cjs\`, \`node scripts/export-library.cjs\`. Запуск \`pnpm test\` также проверяет семантический модуль.
5. **Публикация в публичный репозиторий не автоматическая.** После ревью туда переносятся только проверенные игровые JSON из \`public/\`. Публичный CI проверяет, что статический выпуск не зависит от онлайн-лингвистических сервисов. На данный момент игра ещё не использует новые отношения в генераторе предложений — выгрузка подготовлена как входной формат.

**Границы текущего этапа:** отдельная форма для одобрения грамматических фреймов Конструктикона и FrameBank ещё не сделана. Прямой импорт их \`valency_pattern\` в утверждённый граф **намеренно запрещён**; нужен редактор преобразования ролей, падежей, предлогов и типичных участников. RuWordNet также не включается в опубликованные данные без разрешения прав. Исторический G2P не является проверкой фонетики всех изменённых словоформ.

После выпуска инструменты импорта, временный кэш и среды Python можно удалить из игрового окружения без изменения результатов игры. Сохранить описание версий и процедуру восстановления для будущего пополнения библиотеки.
