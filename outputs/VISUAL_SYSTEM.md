# Единая визуальная архитектура «Забавоград»

**Действующий контракт с 12 ноября 2026 г.** Применяется к текущим шаблонам «Мемори» и «Сортировка» и обязателен для новых игр.

## Принцип

Игра отвечает за правила; тема — за оформление; дизайн-система — за расположение, общие элементы, состояния и анимации. Все шаблоны получают одну и ту же библиотеку слов. Тема не влияет на выбор слов, правила проверки, размер сетки, таймер, жизни и учебные задания.

## Ответственность файлов

| Назначение | Единственное место |
| --- | --- |
| Темы, имена, палитра, ссылки на фон/рубашку/лицевую сторону, комплект кнопок, декоративная сцена, варианты звука | `src/design-system/themes.ts` |
| Единые длительности и задержки | `src/design-system/motion.ts` |
| Общая сцена, фон, карточки, цвета и состояния элементов | `src/design-system/theme.css` |
| Набор контролов: кнопки, вкладки, переключатели | `src/design-system/controls.css` |
| Общие анимации, исчезновение, ошибка, раздача, сниженная подвижность | `src/design-system/motion.css` |
| Отрисовка декоративных слоёв, только согласно реестру | `src/GameUI.tsx` и `src/Effects.tsx` |
| Игровые правила и обработчики кликов | `src/main.tsx`, `src/Sorting.tsx`, `src/model.ts`, `src/sorting.ts` |
| Универсальная геометрия и адаптивная раскладка | `src/styles/layout.css` — без тематических селекторов и изображений |
| Точка импорта слоёв | `src/style.css` — четыре импорта в утверждённом порядке |

В новом CSS **запрещены** селекторы `.space`, `.neutral`, `.forest`: все отличия приходят через переменные, `data-card-style`, `data-scene-motion` и общий реестр. Не создавать CSS вида `forest-memory.css` и `space-sorting.css`. Новую тему добавлять одной конфигурацией и файлами ресурсов.

## Текущие темы

**Нейтральная:** кремово-бумажный фон и акварельные карточки, светлый комплект контролов. Фон медленно движется по общей анимации.

**Космическая:** отдельный фон, акварельные карточки и слои планет/туманностей; контролы из лавандового комплекта. Механика и длительности те же.

**Лесная:** утверждённый фон и отдельные WebP из `public/assets/themes/forest/`: два дерева с покачиванием вокруг основания ствола, куст, папоротник, цветы, три независимо падающих зелёных листа. Реальные WebP рубашки, лицевой стороны и шапки вместо временного градиента. Комплект кнопок sage; правила игр общие.

## Анимации и качество

Единая последовательность: раздача → переворот → мягкое покачивание при ошибке → увеличенная и растворяющаяся пара → экран результата. У сортировки отдельно семантические действия перемещения (FLIP) и проверки ответа. Продолжительность каждого действия — ровно один раз в `motion.ts`, не в шаблоне игры. Движение отключается при `prefers-reduced-motion`. Декорации не перехватывают клики и находятся под игровым слоем.

Для рубашки/лицевой стороны применяется целый WebP как фон: при увеличении не проявляются линии nine-slice. Лесная шапка также использует целый WebP вместо узких сегментов. Весь игровой контент должен укладываться на широком и узком экранах без прокрутки наружу.

## Контроль изменений и выпуск

1. `pnpm test` проверяет реестр, базовый путь, размеры и игровые сценарии.
2. `pnpm check:design-system` распаковывает ассеты, проверяет каждую ссылку, замороженный CSS и то, что компоненты игр не содержат условий по темам.
3. `pnpm build` проверяет TypeScript и собирает файлы.
4. `node scripts/verify-ui-browser.mjs` проверяет и сохраняет снимки в Chromium: 3 темы, разные размеры экрана, карточка с лицевой стороны.
5. Изменения выпускаются в публичный `zabavograd-demo` только после успешной проверки и просмотра снимков. Выпуск и исходники — разные хранилища; само изменение исходного репозитория не обновляет опубликованный сайт.

**Очистка 12 ноября:** файл `legacy.css` удалён. Из исходных стилей убраны 177 специфичных селекторов для старых тем, прежний nine-slice карточек и неиспользуемые анимации. Универсальная раскладка сохранена отдельно в `layout.css`, акварельные контролы — в `controls.css`; новые варианты темы описываются в `themes.ts`. Общие, ещё используемые свойства раскладки не следует удалять без проверки всех игровых экранов.

Для сортировки общие цветовые переменные оформляют также карточки и контейнеры, а длительность реакции при ошибке берётся из того же `motion.ts`.

## Слои сцены и единый выбор темы

В `scene.sprites` перечисляются отдельные файлы декора, координаты, размеры, прозрачность и один из общих типов движения: `float`, `breathe`, `twinkle`, `sway` (покачивание дерева вокруг основания), `fall` (падающий лист), `none`. Объекты отрисовывает `src/design-system/SceneLayers.tsx`, анимации определены только в общем `motion.css`. Для новой темы не надо менять файлы игр или `GameUI.tsx`. Процедурные эффекты задаются `scene.effects.stars/comets`.

`src/design-system/useTheme.ts` сохраняет выбранную тему в общие предпочтения. Переключение между «Мемори» и «Сортировкой» не сбрасывает оформление и другие настройки.

Оформление награды (три звезды) тоже теперь единое: `ScoreStars` из `src/GameUI.tsx`. Задержки звёзд задаются только в `MOTION`, игровые шаблоны передают лишь число полученных звёзд.

## Публикация лесной темы и релиз UI

Исходный архив сверяется с ресурсами уже опубликованной ветки `gh-pages`: контрольные суммы фонового рисунка и восьми отдельных декоративных WebP совпадают. В `gh-pages` уже лежат подготовленные `back.webp`, `front.webp`, `header.webp`. В source-репозитории все 12 файлов находятся в `public/assets/themes/forest/`.

Workflow `build-public-ui.yml` после проверки формирует ветку `ui-release-staging`, содержащую только `index.html` и скомпилированные `assets/index-*.js/css`. **Никакая приватная полная библиотека или новые непроверенные словарные записи туда не попадают.** В публичной ветке `gh-pages` обновляются только эти файлы; действующие `library.json`, `semantic-graph.json`, `assets/words/` сохраняются. В старом публичном index нужно убрать дополнительные CSS-патчи, иначе они будут снова перекрывать дизайн-систему.
