# Схемы действия и RuWordNet: рабочая редакторская последовательность

## Статус

Добавлены адаптер RuWordNet, просмотр вариантов синсетов, визуальный редактор моделей действия, проверка решений и статические игровые выгрузки. Это код для **формирования данных** в приватном репозитории. В игре не нужны RuWordNet, FrameBank, Constructicon, pymorphy3 или G2P. Проверка и публикация содержимого ещё должны выполняться отдельно; код не подтверждает, что в словаре уже есть готовые новые модели.

## A. RuWordNet — подключение уже доступно

Установить в **отдельном Python окружении разработчика**, не в окружении игры:

```sh
python -m pip install ruwordnet
ruwordnet download
```

Версию пакета зафиксировать при первом утверждённом запуске. Загружаемая база RuWordNet относится к отдельному набору данных. На сайте есть одновременно указания **CC BY-SA 4.0** и «non-commercial use». До разрешения расхождения редактор может применять её для исследований, но не копировать выгрузку в публичную игру. MIT-лицензия Python-обёртки не меняет этих условий.

### 1. Выявить возможные соответствия

```sh
python scripts/ruwordnet-suggestions.py --discover
```

Результат: `.local/linguistic-sources/ruwordnet-mapping-candidates.json`. Открыть локально `outputs/Значения-RuWordNet.html`, выбрать этот файл и проверить, какому внутреннему **ID значения** соответствует конкретный синсет. Сохранить `ruwordnet-mappings.json` в `.local/linguistic-sources/`. Не сопоставлять по одному написанию или сходной лексической теме.

### 2. Извлечь предложения связей

```sh
python scripts/ruwordnet-suggestions.py --mapping .local/linguistic-sources/ruwordnet-mappings.json
```

Полученный `ruwordnet-suggestions.json` имеет тот же формат `linguistic_suggestions_v1`, что и Wikidata: никаких изменений в V2, только предложения со статусом `suggested` и `usable_for_generation: false`. Открыть `outputs/Проверка-смысловых-связей.html` и проверить их. Сохранить решения.

```sh
node scripts/semantic-review.cjs apply outputs/library-v2.json .local/linguistic-sources/ruwordnet-suggestions.json semantic-review-decisions.json
```

Подтверждённые RuWordNet-связи получают `verified_research_only`. Они видны в приватном рабочем каталоге, но **не экспортируются** в `public/semantic-graph.json`, в игровые родовидовые индексы или в публичную библиотеку. Потребуется отдельно урегулировать публикационное использование данных; самостоятельные проверенные отношения можно будет вводить как авторские записи с доказательствами, не путать их с копированием лицензируемой базы.

## B. Предложения Конструктикона и FrameBank → собственные модели действия

Источники уже обрабатываются `scripts/linguistic-sources.cjs`:
```sh
node scripts/linguistic-sources.cjs --source constructicon --fetch
node scripts/linguistic-sources.cjs --source framebank --fetch --accept-gpl-review-only
```

Открыть `outputs/Модели-действия.html` локально. Загрузить `outputs/library-v2.json` и один из полученных файлов предложений. Для выбранного **ID глагола** вручную задать короткий смысловой вариант действия и список слотов. Каждый слот содержит **роль**, **падеж**, **предлог**, **обязательность**, **список ID типичных участников**. Например, `patient/acc/""/гвоздь` и `instrument/ins/""/молоток`. Роли пищи, материала и инструмента не объединять при совпадении падежа.

Роли и допустимые ID формируются **своими словами**, без копирования таблиц валентности или корпусных примеров. Подтвердить значение, грамматику, типичность и условия публикации. Для FrameBank перед принятием в публикуемую структуру нужна явная проверка лицензии и независимого авторства; одна галочка не заменяет юридическую экспертизу. Сохранить `speech-frame-decisions.json`.

```sh
node scripts/grammar-review.cjs apply outputs/library-v2.json .local/linguistic-sources/constructicon-suggestions.json speech-frame-decisions.json
```

Для файла FrameBank в команде заменить путь к предложениям. Затем `node scripts/check-library-v2.cjs`, `node scripts/export-library.cjs`. В **каноническом** V2 появляются `speech_frames[]` и журнал `speech_frame_review_history[]`. Генерация выпускает `public/grammar-frames.json` только из проверенных фреймов, без научных исходников. Подготовить отдельный Git-коммит после просмотра diff и проверок.

### Важные ограничения

- Одна модель действия не равна готовому предложению. Генератор должен формировать словоформы по готовым парадигмам, согласовать предлоги/падежи, проверить 2–5 слов и **звуки каждой полученной формы**.
- Типичные участники в моделях должны быть конкретными ID карточек. Указание «предмет» как класса без проверки не подходит.
- В последующем допустимы множественные модели одного глагола, но не бесконтрольное перечисление всех контекстов и предложений.
- Пока в редакторе есть явная приёмка, экспорт и тесты, **но механизм генерации предложений и автоматическая синхронизация публичного релиза ещё не сделаны**.
- Папки `.local/` и `.cache/`, внешние пакеты, модели и исходные тезаурусы **не публикуются** и могут удаляться из игрового окружения. Для повторного пополнения каталога необходимо восстановить build-инструменты.

## C. Контроль перед выпуском

```sh
node --experimental-strip-types --test tests/semantic-review.test.ts tests/grammar-review.test.ts
node scripts/check-library-v2.cjs
node scripts/export-library.cjs
```

Статические `public/library.json`, `public/semantic-graph.json`, `public/grammar-frames.json` — три разных **представления одного основного словаря**, а не три независимо редактируемые библиотеки. В публичном репозитории `zabavograd-demo` есть `scripts/check-offline-release.cjs`, проверяющий их структуру и отсутствие обращений к внешним лингвистическим сервисам в JS-бандле.
