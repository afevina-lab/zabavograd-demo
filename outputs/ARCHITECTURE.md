# Техническое устройство — предложение

31 октября 2026. Не реализовано; поставщики и бюджет не утверждены.

## Основа

Одно приложение с отдельными модулями. Предлагаемый набор: TypeScript, React для кабинета/настроек, Phaser для интерактивных 2D-сцен, серверное API, PostgreSQL для данных, совместимое с S3 хранилище файлов. Не создавать множество независимых сервисов и отдельный код для каждой темы.

Модули: библиотека/разметка, подбор материала, игры, темы, приключения, кабинет/история, доступ/оплата, редактор контента. Игра имеет собственные правила; тема меняет изображения/звук/позиции. Общее поведение (жизни, повтор, пауза, настройки) предоставляется общим игровым слоем. Не пытаться описать любую будущую игру одним универсальным конструктором заранее.

## Данные и файлы

Код и изменения схемы базы — в Git. Картинки/аудио — в файловом хранилище; база содержит идентификаторы и сведения. Отдельные сущности: значения слов, словоформы и звуковая/слоговая разметка, изображения, связи, подсказки, темы, версии приключений, сохранённые конфигурации, ученики, занятия/попытки/этапы, достижения. Обязательные поля и связи проверяются; расширяемые настройки игры имеют собственную версию и проверяемую структуру.

Материалы: черновик → проверено → опубликовано → архив. Учёт происхождения/прав. Искать дубли файлов по содержимому; не смешивать доступ разных владельцев. Не удалять используемые материалы. Неиспользуемые файлы удалять после периода ожидания и проверки ссылок. Изменения базы оформлять последовательными миграциями. Резервное копирование базы И файлов, проверка восстановления.

Сохранённое занятие содержит ссылки/настройки, не копии изображений. История и начатые приключения ссылаются на версии, чтобы редактирование шаблона не меняло прошлое. Не копировать личные данные в тестовую среду.

## Анимация и правила

Механика работает локально в браузере, сервер проверяет доступ и сохраняет значимые события. Не отправлять каждый кадр/движение на сервер. Серверное подтверждение награды проверяет допустимость перехода и предотвращает повторную выдачу; не доказывает качество устного ответа.

Состояния: подготовка → инструкция → игра → завершение → повтор/следующий этап. Пауза останавливает таймеры. Изменение материала перезапускает текущую игру, а не сюжет. Жизни снимаются только педагогом; бомбы сами их не списывают.

Плавное движение/масштаб/поворот — программная анимация. Сложные действия — короткие последовательности кадров; эмоции — смена изображения. Загружать текущую сцену и небольшой запас, не весь мир. Для головоломок использовать проверенные шаблоны либо генерацию с проверкой решаемости.

Предлоги: у объекта допустимые отношения, опорные позиции, масштабы и слои/маски. «За» требует перекрытия, «перед» — переднего слоя, «на» — точки опоры, «в» — подходящего контейнера и маски. Пары собираются автоматически; исходные объекты всё равно размечаются. Грамматическая форма ответа хранится/проверяется отдельно.

## Публикация и затраты

Сначала локальная рабочая версия, затем закрытый тест на вымышленных профилях, затем публичный сайт с доменом, HTTPS, учётными записями, оплатой и мониторингом. Тестовая и рабочая среды отдельные. Выбор страны размещения, оплаты и требований к персональным данным зависит от аудитории и оператора; не утверждён.

Стоимость = сервер/база + объём файлов + запросы/передача + резервные копии + служебные сервисы. Не запускать ИИ и генерацию изображений при каждом ходе. Ограничить загрузки пользователей, размеры файлов и хранение технических журналов; оптимизировать картинки/аудио, использовать кэш. Контролировать бюджеты и квоты, не считать уведомление о расходах гарантированным жёстким лимитом.

Проверенные справочные источники: https://phaser.io/oss/docs/phaser/getting-started/what-is-phaser ; https://developers.cloudflare.com/r2/pricing/ ; https://supabase.com/pricing ; https://supabase.com/docs/guides/platform/cost-control . Это примеры возможностей, не утверждённый выбор облака.

## Первый технический срез

Небольшая проверенная библиотека, редактор карточек/форм, фильтрация с подсчётом доступного материала, мемори с двумя темами. После этого вторая механика на тех же данных проверяет, что переиспользование действительно работает. Тестировать ключевые фильтры, доступ к профилям, сохранение/повтор этапа и защиту от двойной награды.

## Организация разработки — предложение от 1 ноября

Текущая рабочая папка уже доступна Codex; файлы существуют локально. Это прототип каталога и документы, не готовый игровой сайт. Репозиторий Git пока не создан, выгрузки на GitHub не было.

Рекомендуемый следующий шаг — постоянный проект «Забавоград» с одной основной папкой и закрытым GitHub-репозиторием. Перенос делать после выбора места: переместить актуальные документы, данные и поддерживаемые инструменты, проверить запуск, затем убрать прежние рабочие копии. Не включать целиком папку E: или личные педагогические материалы.

В репозитории хранить код, документы решений, схему и начальное наполнение библиотеки, тесты, реестр ассетов. Большие исходники графики/музыки хранить отдельно с резервной копией; при необходимости версионирования отдельных больших файлов использовать Git LFS после оценки объёма. В реестре ассета: постоянный ID, путь, роль/локация, варианты, источник, автор, условия использования, дата получения, ссылка на подтверждение. Профили детей, пользовательские загрузки, пароли и ключи не являются исходниками проекта и в репозиторий не входят.

Git хранит историю правок вместо файлов «финал-2», GitHub — удалённую копию и совместную работу. Публикация работающего сайта и хранение его пользовательских данных — отдельный этап; создание репозитория не запускает платную платформу.

Контекст соседних чатов не считать автоматически общей памятью. В чате «Что такое Codex разработка» просмотрены фрагменты о собственных изображениях, программных эффектах, покадровой/скелетной анимации и адаптивной музыке. Это предложения, а не выбранные зависимости проекта. Лицензионные утверждения об отдельных музыкальных сервисах из того чата здесь не подтверждены. При принятии решения переносить его в PROJECT.md/DECISIONS.md, а сведения о конкретном файле — в реестр ассетов.
