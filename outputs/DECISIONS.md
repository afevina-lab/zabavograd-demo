## 4 ноября 2026 — исключение согласного перед мягким согласным

**Авторское правило автоматизации:** согласный, непосредственно стоящий перед мягким согласным, **не является подходящей целевой фонемой для автоматизации** из-за риска ассимиляции по мягкости. Проверять все согласные и все позиции в слове, включая стечения; [й], [ч'], [щ'] тоже учитываются как мягкие. Пример: в «археолог» [Р] перед [Х'] **исключить** из автоматизации [Р] несмотря на совпадение Р с буквой Р; [К] из буквы Г по-прежнему исключить по другому правилу. **Поиск звука**, в отличие от автоматизации, показывает оба вхождения; иные пригодные звуки слова не блокировать.

Правило учитывается для каждого вхождения звука при генерации технического индекса из транскрипции. Если анализ G2P дал мягкий следующий согласный, исключение действует и для предварительного G2P; статус непроверенного анализа сохраняется. Предыдущие примеры, разрешавшие РХ' для автоматизации в «археолог», отменены.


## 4 ноября 2026 — автоматизация по допустимому звуку и независимый звуковой поиск

- Автор уточнил: **[К] в «археолог» не подходит для автоматизации [К]**, потому что звук [К] образовался из буквы Г. Аналогично [К] из Г в «друг», [Ш] из Ж в «морж» исключаются только как целевые автоматизируемые вхождения; для обычного звукового анализа остаются.
- Пригодность к автоматизации определяется **для каждого вхождения фонемы** через проверяемое сопоставление фонемы с буквенным источником. При несовпадении или неопределённом выравнивании — не выбирать автоматически. **Непроверенная машинная фонетика допускается по решению автора**, если целевой звук однозначно соответствует исходной букве; метка машинного происхождения сохраняется. Не исключать всё слово, если другие его звуки пригодны.
- Для **поиска звука или буквы**: начало, середина, конец и стечение — независимые признаки. Поиск позиции может пересекаться со стечениями.
- Для **автоматизации**: начало, середина, конец — только вне стечений. **Стечения — самостоятельная выбираемая категория в любом месте слова**. Внутри неё подвыборки «С + целевой», «целевой + С», конкретный кластер, например РХ'.
- Для повторного целевого звука есть **один фильтр «два и более»**, без раздельных порогов два/три.
- Отдельные редакторские массивы этих категорий не создаются: они выводятся из `sound_tokens` и букв слова при сборке `public/library.json`, после чего используются готовым индексом в игре.
- Игровой экспорт переведён на универсальный `library-v2.json`. Старый `library-r-draft.json`, его просмотр и одноразовые генераторы удалены: V2 — единственный источник, хранит 409 исходных карточек целиком внутри `legacy_source.raw`.
