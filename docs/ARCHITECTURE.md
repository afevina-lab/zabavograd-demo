# Границы архитектуры

Редактируемая библиотека — только `outputs/library-v2.json`. Экспорт и сборка создают производные файлы; они не используются как независимый редакторский источник.

## Зависимости

- `src/material-types.ts` содержит только типы материала, без зависимостей.
- `src/material-policy.ts` определяет наличие ресурсов и эффективный вес задания.
- `src/material-selection.ts` выполняет взвешенный выбор без повторов; он не зависит от правил конкретной игры.
- `src/learning.ts` и `src/reading.ts` определяют педагогическую пригодность, фонетические ограничения и генерацию материала.
- `src/model.ts`, `src/sorting.ts`, `src/transformations.ts` содержат игровые правила. Экспорт типов и pickWords из model оставлен для совместимости прежних импортов, реализация остаётся единственной.
- TSX-компоненты управляют интерфейсом и вызывают доменные функции. Домен не импортирует React, компоненты, оформление, браузерные хранилища или сеть.
- Темы и анимации находятся в `src/design-system/`; игровой подбор не зависит от оформления.

`node scripts/check-architecture.cjs` проверяет реальные импорты по явным статическим import/export проекта (синтаксис отдельно проверяет TypeScript): запрещает зависимости домена от интерфейса и внешних пакетов, обращение домена к браузеру, неразрешённые локальные импорты и циклы исполняемых зависимостей. Типовые зависимости могут быть циклическими, поскольку не исполняются.

Единственный активный сценарий доставки в gh-pages — `.github/workflows/visual-publish.yml`. Исторические сценарии оставлены отключёнными для аудита. Проверка запрещает повторное включение обнаруживаемых конкурирующих публикаций.

## Порядок проверки

Архитектура → библиотека → игровые тесты → дизайн-система → TypeScript и сборка → автономный выпуск → браузерная проверка → доставка → проверка SHA на опубликованном сайте.

Эти ограничения дополняют проверки поведения: отсутствие архитектурных нарушений само по себе не доказывает педагогическую правильность или визуальное соответствие.
