## Порядок действий после готовности визуальной ветки

1. Зафиксировать новый актуальный main, сохранить его SHA и неизменяемый резервный снимок. Сверить изменения библиотеки по ID, не перезаписывать их старым снимком.
2. Перенести только библиотечные изменения, урегулировать конфликт потребителей, заново запустить инвентаризацию и тесты.
3. Сгенерировать модули из актуального V2; проверить точную логическую эквивалентность, архив, реестр медиа и идентичность игровых JSON. Не создавать второй редактируемый источник.
4. В одном проверенном изменении добавить outputs/library-modules и маркер editorial/library-source-mode.json, удалить outputs/library-v2.json, обновить AGENTS и все активные читатели/писатели и процессы CI. Старый файл восстанавливается из Git, не хранится параллельно как редакторский.
5. Провести полную проверку игр, всех тем и размеров единожды на границе миграции. Отдельно проверить OAuth/клиент редактора, импорт и экспорт, публикацию и откат. Для обычных последующих словарных изменений использовать целевые проверки; не пропускать проверки ассетов, ссылок, архивных данных и генерации.
6. Только после разрешения на переключение — принять PR и проверить реальный релиз. При сбое откатить согласованный набор изменений целиком, не смешивать модули старого и нового поколения. Если после переключения уже приняты новые словарные данные, сначала сохранить их точный снимок и согласовать обратную миграцию, не терять правки.

До этого момента маркер отсутствует, монолит остаётся текущим каноническим источником. Репетиция проверяет отдельный временный checkout, не является готовностью к публикации.
