## Пакет новых WebP и словарных изменений

`library-media-package.cjs MODULES REQUEST INPUT_WEBP_DIR NEW_OUTPUT_DIR [MEDIA_PREVIEW_SHA256]` — локальный ограниченный маршрут для новых файлов, использует тот же `prepare` и `stageVerified`. Input — ровно плоский набор файлов из link_webp, без подмен существующих путей, до 2 МиБ на файл / 24 МиБ на пакет. SHA-256, RIFF, декодирование Pillow, размеры до 2048, статичность и наличие прозрачной и видимой областей обязательны; визуальная оценка остаётся отдельной. Candidate требует оба предварительно просмотренных SHA (library_preview_sha256 в JSON и media_preview_sha256 аргументом). CI реконструирует кандидат, проверяет согласование и отказ при неверном SHA или повреждении WebP. Пока нет удалённой передачи бинарных файлов и атомарного принятия пакета в Git; это отдельный этап. Старый простой link_webp для уже существующих файлов сохранён как та же операция, не отдельный импортёр. Не применять тестовые данные.

## Удалённая передача новых WebP через общий edit workflow

Ветка `library-media-request/<slug>` содержит `editorial/requests/library-media.json` — `{version:1,request:<existing modular import request>,media_preview_sha256?:<pin only for candidate>}` — и ровно указанные файлы `editorial/requests/media/<basename>.webp`. Тот же workflow `library-modular-edit-rehearsal.yml` читает данные точного коммита через git ls-tree/cat-file без checkout или запуска кода request-ветки, проверяет режим обычного файла, лимиты и SHA каждого бинарного файла; доверенная реализация из интеграции вызывает существующий media-package. Результат изолирован в `library-media-result/<slug>-<12 SHA>` и artifact. Запрос не переносит данные в main. Candidate требует оба просмотренных отпечатка. Тесты транспорта имитируют Git; реальный push probe проверяется отдельно. GitHub connector позволяет загружать бинарные blob base64, без помещения изображения в JSON. Интерфейс редактора пока не подключён к этой передаче; автоматическая сборка принимаемого Git-коммита остаётся следующим этапом.

## Атомарный Git-коммит кандидата

`library-commit-package.cjs BASE_COMMIT BUNDLE_DIR LIBRARY_PREVIEW_SHA256 [MEDIA_PREVIEW_SHA256]` работает только в чистом checkout после канонического переключения. Для обычного пакета используется существующий guarded apply, для медиа — replayCandidate через исходный media-package, точные отпечатки и сравнение всех файлов/байтов с воспроизведённым пакетом. Проекция реестра формируется общим импортёром. Временный Git index позволяет построить один commit-tree с новым манифестом, изменёнными модулями, реестром и WebP; проверяется точный набор путей. HEAD, refs, checkout и рабочий index не меняются. Статус validated_unreferenced_commit_not_approved; это объект Git, а не принятие или публикация. CI создаёт временный detached worktree с модульным источником, формирует два коммита, сверяет байты реестра/изображения и проверяет отказ при подмене. Без разрешения автора не переключать канонический источник и не отправлять коммит в main. Для реального принятия понадобится отдельное согласованное обновление ref с проверкой точного base SHA.

## Серверное чтение после переключения

Кэш теперь распознаёт маркер канонического источника на точном Git-коммите. При наличии маркера отклоняет монолит или отсутствующие модули; без маркера отклоняет неактивированную генерацию модулей. Читает только дерево модулей, проверяет Git blob каждого файла, manifest, точный набор модулей и логический SHA через общий store.loadFiles. Предыдущие проверенные blobs переиспользуются по SHA, скачиваются только изменившиеся файлы (пакетами по восемь параллельных запросов). Никакого checkout или выполнения удалённого кода. Холодный старт требует загрузки всех модулей; реальная задержка и OAuth на хостинге не измерены. Источник всё ещё фиксирован на интеграции; переключение SOURCE_REF на будущий main и отключение legacy API остаются этапом cutover. CI проверяет реальную модульную генерацию через имитацию Git transport.

## Общий источник удалённых запросов и индекса

Оба экспериментальных workflow теперь используют `library-request-source.cjs prepare`: до cutover — проверенная временная генерация за пределами checkout, после cutover — существующая каноническая директория без init, копирования или переменной переопределения. Запросы чтения проходят общий runner с точной проверкой логического SHA. Пакеты редактирования используют полученную директорию, не изменяя её. Источник и scope всё ещё интеграционные, публикация main не переключена. В `library-index.yml` добавлены модульные пути, маркер и зависимости восстановления в фильтры запуска и проверку устаревания; изменения начнут действовать в main только при согласованном переносе. Репетиция cutover сравнивает реальные remote query, кандидат и редакторский индекс до и после удаления монолита. Пробные правки не предназначены для принятия.

## Сохранение черновиков интерфейса

Локальное восстановление операций и билета отделено от подтверждения preview: после перезагрузки новый клиент перепроверяет отчёт по исходному запросу. Никаких автоматических записей или принятия пакетов. При несовпадении текущего SHA редактирование блокируется. Действует в пилоте, не на опубликованном сайте. Импорт скачанного черновика добавлен следующим шагом; сквозная проверка OAuth остаётся отдельной задачей.

Импорт скачанного черновика подключён к пилоту: без автоматического изменения источника, с точным SHA и сравнением старых полей для неотправленных правок. Билеты требуют повторной проверки отчёта. Слияние устаревших черновиков не предусмотрено. Следующий шаг — целевые проверки интерфейса и фактическое испытание OAuth на отдельном сервере.

## Целевые проверки редактора

Классификатор интеграции использует четыре строгих режима: docs (точный перечень документов), client (изолированные modular-client/modular-ui и их тесты), adapter (modular-bridge/modular-read-cache и их тесты, также совместно с client), full (всё прочее, неизвестные изменения или ручной запуск). `npm run test:library-editor` — единый набор синтаксических проверок и всех тестов редактора; применяется и в сокращённых, и в полной проверке без установки npm-зависимостей. Adapter дополнительно готовит проверенный реальный снимок, сравнивает SQLite-ответ с каноническим модульным транспортом, проверяет чистоту checkout. Не сокращаются изменения авторизации, server.mjs, Docker, загрузчика, HTML/CSS, данных, workflows, генераторов, формата хранения или смешанные с ними. Ручной full остаётся обязательным перед cutover. Последний полный прогон перед изменением 45865244543: 80 тестов плюс проверки реальных данных, 186 секунд job rehearsal; сокращённые маршруты необходимо подтвердить отдельными фактическими изменениями. Визуальный publisher не изменяется.

## Читатели внешних словарей

Constructicon, FrameBank, Wikidata и RuWordNet по умолчанию читают единственный выбранный источник через существующий общий адаптер. В отчёт добавлен library_source с режимом и SHA. Для RuWordNet сохранён явный --library как локальный исследовательский снимок с отдельной маркировкой, выход только в .local или вне репозитория, не поверх входного файла. Лицензии и режим review-only не изменены; данные не утверждаются и не экспортируются в игры. CI использует искусственный локальный CSV и имитацию RuWordNet, а также проверяет чтение реальной канонической генерации без монолита. Сетевые загрузки внешних источников не выполняются.
