# Этап 4 — аудит и обратимое модульное хранение

Рабочая ветка основана на main 6ddc01703be09341eba83d8a7bd7c13a89cae9e4; страховочная ветка backup/before-modular-library-20261126. Не является переключением источника. outputs/library-v2.json остаётся единственным редактируемым источником. Не редактировать экспериментальные модули и не публиковать их на gh-pages.

Команда node scripts/library-storage-audit.cjs NEW_OUTPUT_DIR строит отчёт audit.json и обратимый layout в новой папке. В CI дополнительно --verify-runtime (только одноразовый checkout) сравнивает SHA-256 трёх выгрузок, созданных одним и тем же exporter до и после сборки. В finally восстанавливает оригинальные байты всех затронутых файлов. Не использовать этот режим на рабочей копии.

## Модель
- Группы: core (включая пока не классифицированные поля), phonetics, morphology, semantics, syllables, translations, illustrations, machine, archive; отдельные категории, отношения, метаданные.
- Стабильный префикс SHA-256 ID, 256 возможных корзин на группу, только непустые. Не делить по лексическим темам; не объединять омонимы. Строка JSON на запись внутри массива для малого diff. Не менять идентификаторы.
- entry-order и relation-order сохраняют порядок записей и ключей для эквивалентности. manifest содержит размеры, хэши каждого модуля, исходный SHA-256. Модули проверяются при сборке. Явный null и отсутствующий ключ различаются; неизвестные поля сохраняются.
- Архив не удаляется: legacy_source выделяется в отдельную группу. Проверки показывают точные совпадения старой грамматики и фонетики с действующими полями, а также некоторых машинных предложений. Совпадение не даёт разрешения удалить поле, данные или происхождение.
- Отчёт разделяет размер исходного файла, размер значений отдельных полей (без форматирования и ключей), объём архива и размеры экспериментального layout.

## Перед реальным переключением
1. Изучить отчёт на фактических данных; оценить количество и размер файлов, пригодность для GitHub-коннектора. Уточнить разбиение по результату, не менять схему только ради уменьшения размера.
2. Проверить ссылки на legacy_source и все читающие/пишущие инструменты (JS, Python, HTML/editor-service, CI). Перевести запись на единый модульный интерфейс. Не поддерживать два независимых редактируемых источника.
3. Убрать повторение только там, где восстановление прежнего значения и происхождения доказано; заменить фиксированные исторические проверки инвариантами без ослабления целостности.
4. Сформировать новую резервную точку актуального main, провести полный roundtrip и сравнить runtime, тесты игр, редактор и индексы. Затем переключить canonical source одним контролируемым PR. Старый V2 при необходимости генерируется как совместимая производная выгрузка.
5. Сверить публикацию и возможность отката. Отдельно адаптировать анализаторы и редактор.

На данном этапе ничего не удаляется, словарные данные не меняются. Результат CI и экспериментальный layout доступны как артефакт, не второй мастер.

## Сравнение размеров и устранение точных дублей — эксперимент 2

`library-storage-optimize.cjs` сравнивает семь вариантов (16/32/64/256 корзин и смешанные размеры); выбирает из испытанных вариантов с общими неизменяемыми значениями тот, который имеет минимум файлов при размере каждого рабочего модуля до 128 KiB. Служебные manifest/order считаются отдельно. Точный roundtrip обязателен для каждого варианта.

Совпадающие `legacy_source.raw.speech/grammar` и `phonetic_tags.data/morphology.data` хранятся в прототипе один раз как неизменяемое значение, проверяемое SHA-256; ссылки только на это значение, не на текущую редакторскую запись. При чтении создаются независимые копии. Отличающиеся данные или порядок ключей не объединяются; черновой анализ не меняется. Никакого удаления исторической версии или её происхождения. Изменение активного поля после перехода должно создавать новую ссылку, не менять старое содержимое. Пока переход не выполнен: writer для этих ссылок ещё не подключён. Выбранный layout с явным encoding и отчёт optimization.json сохраняются в артефакте, экспорт сравнивается с исходником.
