## Снимок и анализ

Store inspect/export возвращают логический SHA и снимок. init SOURCE NEW_DIR создаёт независимую генерацию, patch DIR PACKET NEW_DIR — отдельный кандидат. Обязательны проверка схемы, медиа, архива 409 исходных записей, хэшей и полный валидатор. SQLite временный, параметризованный, без произвольного SQL.

analyze-pending-words.py --output DRAFT --report REPORT создаёт черновик; annotate-analysis.cjs DRAFT дополняет буквенным соответствием; merge-auto-analysis.cjs DRAFT NEW_DIR принимает только pending-поля, с точным SHA/ID/леммой/значением. Не заменять имеющиеся предложения, активные формы или архив. G2P в CI покрывается синтетическими тестами; реальный анализ требует установленного анализатора. Старые типы Марковой не переносить автоматически. Исторический черновик удалён после сверки; уникальные остатки machine_analysis.historical_draft не участвуют в генерации. Полный исходник в Git (CLEANUP_LOG).

## Редакторские предложения

### Фонетические исправления: отдельный черновик

Удалённый редактор допускает только создание `/phonetic_tags/review_proposal` (existing=false) с точным base.status и base.sound_tokens из существующей карточки, source=editorial_review, status=suggested, usable_for_generation=false, sound_tokens, stress_syllable, syllable_count, stressed_vowel и reason. Валидатор проверяет допустимые фонемы (без V), гласные, номер ударного слога, ударную гласную и неизменность исходного состояния. Буквенно-звуковое соответствие диагностируется существующим sound-index без допуска к автоматизации. Предложение хранится отдельно, не заменяет старый машинный или редакторский анализ и не меняет архив. Индекс помечает наличие предложения. Ограничение — одиночные русские слова; обновление действующего разбора, повторное редактирование предложения и изменение статусов требуют отдельного утверждённого механизма, учитывающего новую слоговую классификацию. CI проверяет реконструкцию кандидата и совпадение игровых выгрузок с исходником; проба слова кот не является методическим изменением.

### Типизированные семантические предложения

`semantic_operations` в удалённом редакторском пакете — список объектов type, subject, object, reason. Каждый участник — точный снимок {id,lemma,meaning}, null для отсутствующего значения; обе карточки должны быть словами и не алиасами. Используется существующий список типов semantic-review, симметричные пары и has_part/part_of нормализуются, проверяются существующие связи и открытые предложения, новые циклы is_a и part_of, часть речи для синонимов/антонимов/противопоставлений, признак обобщающего понятия для is_a. Предложения хранятся в semantic_review_proposals исходной карточки в семантическом модуле, отдельно от действующих relations. Статус suggested, usable_for_generation=false; импорт внешних лицензированных источников и утверждение/удаление связей пока не допускаются этим маршрутом. Очередь semantic-proposals показывает оба конца ожидающих проверки связей. CI проверяет реконструкцию пакета, равенство активного графа и очередь. Тестовая связь не редакторское решение.

### Решения по предложениям

`review_decisions` — отдельный запрос на уже существующие предложения (operations=[]), с точным SHA предложения, ID владельца, действием и обоснованием. Семантическое принятие независимой редакторской пары требует sense_checked, typical_for_children, independently_authored=true. Проверяются текущие значения, дубли, циклы; новая связь добавляется без изменения прежних. Игровой валидатор допускает новую ревизию только при совпадении записи решения, хэша предложения и точных ID связи. История `editorial_decision_history` сохраняет исходное предложение и решение; отклонение убирает его из очереди, но не из истории. Не заявляется подтверждение человеком: human_reviewed=false, доверенный редакторский запрос не является аутентификацией методической проверки. Фонетическое отклонение поддерживается, активация пока заблокирована до согласования производных полей и слоговой классификации. Отдельная очередь phonetic-proposals показывает такие предложения. Внешние источники не поддерживаются этим маршрутом. CI проверяет принятие и отклонение на временном кандидате; это не изменение живой библиотеки.

### Безопасное применение пакета к новой генерации

`node scripts/library-apply-bundle.cjs SOURCE_DIR BUNDLE_DIR NEW_DIR EXPECTED_PREVIEW_SHA256` требует контрольную сумму из независимо просмотренного preview (не брать её из самого пакета). Проверяет точную исходную генерацию, статус, воспроизводит все ограниченные операции и решения, сверяет отчёт, манифест, точный набор файлов и байты каждого изменённого модуля с результатом воспроизведения. Отклоняет неизвестные файлы, симлинки, повреждения, конфликт источника и уже существующий каталог. Не копирует непроверенное содержимое: создаёт заново рассчитанную генерацию, прогоняет полный валидатор и архивную проверку, затем атомарно переносит в отдельный новый каталог. Статус staged_generation_validated_not_activated: это не переключение канонического источника и не публикация. CI применяет весовой пакет, семантическое предложение и последующее решение; отдельно проверяет отказ устаревшего и повреждённого пакета. Пробные данные не предназначены для утверждения.


## Типизированный импорт

`import_operations` в отдельном запросе preview/candidate поддерживает create_noun (новое русское существительное, точное значение, существующие категории, предложенный вес; фактический вес 0, ветки не включены по умолчанию, анализ pending) и link_webp (точный ID/лемма/значение, предварительно размещённый WebP, SHA-256, явная отметка проверки). Дубли написания с учётом ё/е, уже используемые пути и известные SHA, замена существующих смысловых карточек и вариантов запрещены. Проверяется контейнер WebP и файл, не качество картинки. Строгий валидатор учитывает отдельное число новых ID, проверяет новые связи и архив; replay поддерживает этот пакет. `projectRegistry` формирует только добавление новых смыслов к прежнему реестру, не публикует его. Для новых файлов использовать media-package или удалённый медиа-запрос. Не поддерживаются создание новых категорий, омонимов, глаголов, признаков, активация черновиков и замена старых картинок. Тестовая запись и картинка создаются исключительно в CI.

## Словоформы: единый механизм вместо исторического скрипта

Алгоритм безопасного допуска перенесён в существующий морфологический анализатор `extend-morphology-20261123.py --safe-entry ID [--safe-entry ID...] --report REPORT --candidate-dir NEW_DIR` (1–30 точных ID, pymorphy3 2.0.6, только модульный источник). Сохраняются архив, предложения и прежние одобрения; формы сверяются с точным разбором и уже существующим предложением, исключаются неоднозначности, неподтверждённое множественное число и автоматический счёт. Результат machine_checked, human_reviewed=false, отдельный кандидат, не автоматическая публикация. Проверка writer отдельно ограничивает изменённые поля и ключи словоформ; математическая проверка совпадения парадигмы выполнена локальным Python-анализатором, не заявляется человеческая проверка. Исторический activate-safe-forms удалён, специальный старый обход для партии от 23.11 не переносится (новые слова должны иметь предложение). Полный валидатор поддерживает явный --candidate-dir, не переопределяя канонический источник. CI сначала генерирует игровой JSON для регрессионных тестов изображений и слов. Исторические скрипты удалены.

## Пакет новых WebP и словарных изменений

`library-media-package.cjs MODULES REQUEST INPUT_WEBP_DIR NEW_OUTPUT_DIR [MEDIA_PREVIEW_SHA256]` — локальный ограниченный маршрут для новых файлов, использует тот же `prepare` и `stageVerified`. Input — ровно плоский набор файлов из link_webp, без подмен существующих путей, до 2 МиБ на файл / 24 МиБ на пакет. SHA-256, RIFF, декодирование Pillow, размеры до 2048, статичность и наличие прозрачной и видимой областей обязательны; визуальная оценка остаётся отдельной. Preview привязывает SHA библиотеки, операций, исходного/результирующего реестра и файлов. Candidate требует оба предварительно просмотренных SHA (library_preview_sha256 в JSON и media_preview_sha256 аргументом). В новом каталоге вне репозитория сохраняются изменённые модули, файлы media/public и проекция реестра media/image-library.json. Полный валидатор читает временное дополнение, не изменяя checkout. CI реконструирует кандидат, проверяет согласование и отказ при неверном SHA или повреждении WebP. Удалённая передача и атомарная подготовка коммита описаны в LIBRARY_REMOTE.md. Старый простой link_webp для уже существующих файлов сохранён как та же операция, не отдельный импортёр. Не применять тестовые данные.

## Атомарный Git-коммит кандидата

`library-commit-package.cjs BASE_COMMIT BUNDLE_DIR LIBRARY_PREVIEW_SHA256 [MEDIA_PREVIEW_SHA256]` работает только в чистом checkout в каноническом режиме. Для обычного пакета используется существующий guarded apply, для медиа — replayCandidate через исходный media-package, точные отпечатки и сравнение всех файлов/байтов с воспроизведённым пакетом. Проекция реестра формируется общим импортёром. Временный Git index позволяет построить один commit-tree с новым манифестом, изменёнными модулями, реестром и WebP; проверяется точный набор путей. HEAD, refs, checkout и рабочий index не меняются. Статус validated_unreferenced_commit_not_approved; это объект Git, а не принятие или публикация. CI создаёт временный detached worktree с модульным источником, формирует два коммита, сверяет байты реестра/изображения и проверяет отказ при подмене. Без разрешения автора не переключать канонический источник и не отправлять коммит в main. Для реального принятия понадобится отдельное согласованное обновление ref с проверкой точного base SHA.


## Инвентаризация и ограничения

node scripts/library-consumer-audit.cjs REPORT.json — статический поиск ссылок на старые источники и архив; потенциальный writer не равен доказанной записи. Динамические обращения проверять отдельно. Внешние словари дают предложения с SHA/provenance, не автоматическое утверждение. Никаких тестовых данных в рабочей библиотеке. Открытые задачи: [LIBRARY_CUTOVER.md](LIBRARY_CUTOVER.md).
