# Подготовка переключения модульного источника (26.11.2026)

Отдельная интеграционная ветка refactor/library-modular-integration-20261126 содержит только библиотечные изменения из PR 26 и 27 и новый адаптер. Новую визуальную ветку, main, gh-pages и действующие процессы публикации не трогать. На этом шаге намеренно нет PR в main: старый визуальный workflow ставит все PR в общую очередь. Проверки запускаются отдельным push workflow только на этой ветке, read-only. Перед финальным PR пересобрать интеграцию от будущего актуального main после завершения визуальной ветки, проверить конфликты и повторить инвентаризацию.

## Store
- `node scripts/library-store.cjs init outputs/library-v2.json NEW_DIR` создаёт проверенную модульную генерацию (32 корзины на группу).
- `... inspect DIR` возвращает логический SHA-256 и счётчики; `... export DIR NEW_JSON` собирает совместимый V2 с исходным порядком.
- `... patch DIR PACKET NEW_DIR` создаёт отдельного кандидата с source_sha256 из inspect, ожидаемыми значениями и version:1. Исходная генерация не меняется. Файл manifest меняется вместе с модулями; редактирование отдельных файлов без пересчёта хэшей не допускается.
- Все модули и их набор проверяются, SHA логической библиотеки вычисляется из канонической сериализации. Это не Git blob SHA существующего файла. Патч проходит schema/media validator, затем обязательны существующий полный валидатор и методические проверки. Старый источник не изменяется.
- Архивная и актуальная копии восстанавливаются независимо; проверка сохранности архива применяется при подготовке патча. В существующем check-library-v2.cjs есть требование равенства активных полей legacy speech/grammar архиву. До переключения надо заменить именно это историческое требование на проверку неизменности архива и сохранения исходной информации; не делать это без реального теста и снимка архива.
- Физическое переключение на новый canonical source пока не сделано. В CI проверяется полная сборка, реальный небольшой кандидат, полный валидатор и восстановление checkout.

## Инвентаризация
`node scripts/library-consumer-audit.cjs REPORT.json` сканирует отслеживаемые скрипты, тесты, редактор, workflows и исходники; выдаёт места прямых ссылок на V2, машинные предложения и legacy_source и консервативные кандидаты в writer. Динамические ссылки проверять отдельно. Не переписывать исторические миграции как действующие редакторы; маркировать их устаревшими/заблокированными после переключения.

## План интеграции
1. Сверить новую визуальную ветку после её принятия в main, включая изменения в exporter, library loader, CI и модели материалов. Не переносить UI/CSS из старого main.
2. Перевести активные читатели/писатели на store и обеспечить общий API для Python/Node. Снимок V2 для прежних анализаторов допускается только как производный/временный; возвращать изменения через сравнение и валидацию. Веб-редактор — сохранить через новый механизм пакетов.
3. После проверки всех writer и запрета прямой записи в V2 сделать одним PR переключение источника. Обновить AGENTS, export/refresh/index, workflow и editor-service; проверить полное совпадение выгрузок, свежесть индексов, архива и откат. SQLite только производный индекс. 

### адаптер чтения (26.11.2026)

Явный режим `ZABAVOGRAD_LIBRARY_MODULES=/path/to/modules` позволяет экспортёру, валидаторам, CLI выборки, генератору индекса и Python-анализатору читать проверенный модульный источник напрямую. При отсутствии переменной по-прежнему используется действующий V2; если переменная задана неверно, аварийный отказ без fallback. Прямые записи CLI и merge-auto-analysis в модульном режиме блокируются. Для Python доступен read-only `library_source.read_library()`. Это репетиционный режим, не переключение канонического источника. Проверка неизменности архива подготовлена, исторический валидатор ещё не изменён до фиксации контрольной суммы реального архива.

### Защита исторических данных и проверка потребителей

Зафиксирован контрольный SHA-256 всех 409 записей `legacy_source` из исходного проверенного main (см. `editorial/library-archive-baseline.json`, подтверждённый запуск 45741102745). В интеграционной версии полного валидатора проверяется неизменность архива, а не обязательное равенство архива и текущего анализа. Остальные требования сохранены, включая старые ID и леммы. Контрольная сумма не обновляется автоматически. Тесты должны подтверждать допустимость изменения актуального поля и отказ при изменении архива. Прямой remote candidate для монолита блокируется при явном модульном режиме до адаптации протокола. `sync-runtime` принимает явный модульный источник; прежний режим по умолчанию сохранён.

### Адаптация записи анализатора морфологии

`extend-morphology-20261123.py` в режиме модулей читает через общий адаптер. `--report PATH` задаёт отчёт, `--candidate-dir NEW_DIR` создаёт отдельный проверенный кандидат, `--write` запрещён. `library-analysis-writer.cjs` принимает снимок результата и SHA исходной генерации, сверяет каждый изменённый объект, разрешает только добавление новых форм к уже существующим предложениям pymorphy3 со статусом suggested и usable_for_generation=false. Старые формы, активные формы, идентификаторы, статусы, архив, категории, связи, изображения и прочие поля защищены. Новые данные не утверждаются автоматически. Кандидат проходит полный валидатор; при отказе удаляется только вновь созданный каталог кандидата. При отсутствии изменений каталог не создаётся. Это первый специализированный writer, не универсальный импортёр. Заполнение первоначальных фонетических/морфологических предложений и операции над связями требуют отдельных ограниченных режимов; прежний merge пока заблокирован в модульном режиме.
