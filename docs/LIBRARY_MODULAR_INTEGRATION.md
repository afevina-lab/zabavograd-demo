# Подготовка переключения модульного источника (26.11.2026)

Отдельная интеграционная ветка refactor/library-modular-integration-20261126 содержит только библиотечные изменения из PR 26 и 27 и новый адаптер. Новую визуальную ветку, main, gh-pages и действующие процессы публикации не трогать. На этом шаге намеренно нет PR в main: старый визуальный workflow ставит все PR в общую очередь. Проверки запускаются отдельным push workflow только на этой ветке, read-only. Перед финальным PR пересобрать интеграцию от будущего актуального main после завершения визуальной ветки, проверить конфликты и повторить инвентаризацию.

## Store
- `node scripts/library-store.cjs init outputs/library-v2.json NEW_DIR` создаёт проверенную модульную генерацию (32 корзины на группу).
- `... inspect DIR` возвращает логический SHA-256 и счётчики; `... export DIR NEW_JSON` собирает совместимый V2 с исходным порядком.
- `... patch DIR PACKET NEW_DIR` создаёт отдельного кандидата с source_sha256 из inspect, ожидаемыми значениями и version:1. Исходная генерация не меняется. Файл manifest меняется вместе с модулями; редактирование отдельных файлов без пересчёта хэшей не допускается.
- Все модули и их набор проверяются, SHA логической библиотеки вычисляется из канонической сериализации. Это не Git blob SHA существующего файла. Патч проходит schema/media validator, затем обязательны существующий полный валидатор и методические проверки. Старый источник не изменяется.
- Архивная и актуальная копии восстанавливаются независимо; проверка сохранности архива применяется при подготовке патча. В существующем check-library-v2.cjs есть требование равенства активных полей legacy speech/grammar архиву. До переключения надо заменить именно это историческое требование на проверку неизменности архива и сохранения исходной информации; не делать это без реального теста и снимка архива.
- Физическое переключение на новый canonical source пока не сделано. В CI проверяется полная сборка, реальный небольшой кандидат, полный валидатор и восстановление checkout.

## Инвентаризация
`node scripts/library-consumer-audit.cjs REPORT.json` сканирует отслеживаемые скрипты, тесты, редактор, workflows и исходники; выдаёт места прямых ссылок на V2, машинные предложения и legacy_source и консервативные кандидаты в writer. Динамические ссылки проверять отдельно. Не переписывать исторические миграции как действующие редакторы; маркировать их устаревшими/заблокированными после переключения.

## План интеграции
1. Сверить новую визуальную ветку после её принятия в main, включая изменения в exporter, library loader, CI и модели материалов. Не переносить UI/CSS из старого main.
2. Перевести активные читатели/писатели на store и обеспечить общий API для Python/Node. Снимок V2 для прежних анализаторов допускается только как производный/временный; возвращать изменения через сравнение и валидацию. Веб-редактор — сохранить через новый механизм пакетов.
3. После проверки всех writer и запрета прямой записи в V2 сделать одним PR переключение источника. Обновить AGENTS, export/refresh/index, workflow и editor-service; проверить полное совпадение выгрузок, свежесть индексов, архива и откат. SQLite только производный индекс. 

### адаптер чтения (26.11.2026)

Явный режим `ZABAVOGRAD_LIBRARY_MODULES=/path/to/modules` позволяет экспортёру, валидаторам, CLI выборки, генератору индекса и Python-анализатору читать проверенный модульный источник напрямую. При отсутствии переменной по-прежнему используется действующий V2; если переменная задана неверно, аварийный отказ без fallback. Прямые записи CLI и merge-auto-analysis в модульном режиме блокируются. Для Python доступен read-only `library_source.read_library()`. Это репетиционный режим, не переключение канонического источника. Проверка неизменности архива подготовлена, исторический валидатор ещё не изменён до фиксации контрольной суммы реального архива.

### Защита исторических данных и проверка потребителей

Зафиксирован контрольный SHA-256 всех 409 записей `legacy_source` из исходного проверенного main (см. `editorial/library-archive-baseline.json`, подтверждённый запуск 45741102745). В интеграционной версии полного валидатора проверяется неизменность архива, а не обязательное равенство архива и текущего анализа. Остальные требования сохранены, включая старые ID и леммы. Контрольная сумма не обновляется автоматически. Тесты должны подтверждать допустимость изменения актуального поля и отказ при изменении архива. Прямой remote candidate для монолита блокируется при явном модульном режиме до адаптации протокола. `sync-runtime` принимает явный модульный источник; прежний режим по умолчанию сохранён.

### Адаптация записи анализатора морфологии

`extend-morphology-20261123.py` в режиме модулей читает через общий адаптер. `--report PATH` задаёт отчёт, `--candidate-dir NEW_DIR` создаёт отдельный проверенный кандидат, `--write` запрещён. `library-analysis-writer.cjs` принимает снимок результата и SHA исходной генерации, сверяет каждый изменённый объект, разрешает только добавление новых форм к уже существующим предложениям pymorphy3 со статусом suggested и usable_for_generation=false. Старые формы, активные формы, идентификаторы, статусы, архив, категории, связи, изображения и прочие поля защищены. Новые данные не утверждаются автоматически. Кандидат проходит полный валидатор; при отказе удаляется только вновь созданный каталог кандидата. При отсутствии изменений каталог не создаётся. Это первый специализированный writer, не универсальный импортёр. Заполнение первоначальных фонетических/морфологических предложений и операции над связями требуют отдельных ограниченных режимов; прежний merge пока заблокирован в модульном режиме.

### Первичный анализ в модульном режиме

`analyze-pending-words.py --output DRAFT --report REPORT [--limit N] [--weight W] [--morphology-only]` создаёт отдельный черновик с SHA-256 и Git blob SHA точного прочитанного снимка. Ограниченные запросы сортируются по весу/ID. `annotate-analysis.cjs DRAFT` может дополнить черновик буквенным соответствием. `merge-auto-analysis.cjs DRAFT NEW_DIR` в явном модульном режиме вызывает `library-initial-analysis.cjs`: только поля со статусом pending_automatic_analysis, не заменяет существующие предложения или активные формы, отклоняет несовпадающие ID/лемму/значение и несвежий черновик; архив не меняется. Для исторических записей предложения сохраняются отдельно. Фонетические предложения сохраняют действующее правило допустимости буквенного соответствия, но не переносят старый кандидат типа Марковой в новую классификацию. Неполученные/невалидные данные пропускаются. Общий stageVerified создаёт отдельного кандидата и запускает полный валидатор. G2P в CI здесь не устанавливается: фонетический путь покрывается синтетическими тестами, реальный прогон требует установленного анализатора. Старый монолитный режим сохранён до миграции.

### SQLite: производный индекс (Node 24, без внешних зависимостей)

`node scripts/library-sqlite.cjs build NEW_DB` создаёт новый проверенный индекс из выбранного источника (явный модульный режим или старый V2). `node scripts/library-sqlite.cjs query DB REQUEST_JSON` открывает его только для чтения, сверяет SHA текущего источника и отклоняет устаревший индекс. До 40 строк; параметризованные фильтры вместо произвольного SQL. Пример: {"weight":100,"sounds":["к"],"exclude_sounds":["р","р'"],"has_image":true,"limit":20}. Другие параметры: id, lemma, prefix, kind, pos, category (включая дочерние), default_category, lexical_default, phonetic_status, morphology_status, stored_phonetics, syllable_type (только свежая разметка), position, cluster, min_occurrences (на каждый целевой звук), form_key, form_origin, relation_type, relation_status, offset. Отношения по умолчанию verified, формы по умолчанию machine_checked_active. Фонетика только сохранённая в карточках, без подстановки внешнего черновика; допустимость по существующему sound-index. Исключение звуков проверяет все сохранённые вхождения, неизвестная фонетика не подтверждает отсутствие звука. Это редакторский поиск, не новый движок игровых заданий; веса — базовые, картинки — число привязанных вариантов, не отдельная проверка файлов. Слоговой индекс при несовпадении обоих исходных blob SHA не используется. БД — временный артефакт CI, не источник и не публикуется. Для запросов из чата ещё нужен отдельный GitHub-протокол. Первичный анализ дополнен --initial-only, чтобы не расходовать порцию на уже созданные кандидаты.

### Удалённый поиск SQLite

Подключена команда query/sqlite к bounded request runner и отдельный экспериментальный workflow library-sqlite-remote-rehearsal. Источник — снимок интеграционной ветки, не текущий main; результат содержит source_commit и source_sha256. Запрос не создаёт кандидатов и не записывает библиотеку. Временный индекс удаляется, результат ограничен 96 КиБ / 40 строк. Для следующей страницы указывается SHA предыдущего результата. См. LIBRARY_REMOTE.md.

### Удалённое модульное редактирование (репетиция)

Новый `library-modular-request.cjs MODULES REQUEST NEW_OUTPUT_DIR` использует двухэтапный протокол. `preview` требует SHA источника и до 30 операций с ID, JSON Pointer, точным ожидаемым значением и заменой; возвращает preview_sha256. `candidate` требует тот же пакет и preview_sha256. Полный валидатор и защита архива выполняются до выдачи отдельного кандидата; исходник не меняется. Пока разрешены только базовый вес и отдельные текстовые поля morphology.data.diminutive/plural_nominative. Это редакторский запрос, не автоматическое утверждение; иные пути, статусы, связи, медиа, ID, архив и произвольные поля запрещены. Фонетический пакет потребует отдельной проверки согласованности. Публикуются только result.json, новый manifest и изменённые/добавленные модули; удаления перечислены в отчёте. CI восстанавливает полноценного кандидата из этого дельта-пакета и оригинальных модулей и проверяет SHA. Ветка library-edit-request/<slug> от интеграционной ветки содержит только editorial/requests/library-edit.json (коммит запроса), отдельный workflow создаёт library-edit-result/<slug>-<SHA12> с результатом. Отдельные ветки отчётов не предназначены для merge в main. Только доверенные участники репозитория. Используется снимок интеграции, не live main; при движении интеграционной ветки публикация отклоняется. Тестовое изменение веса сумки 100→70 не является редакторским решением и не должно переноситься в библиотеку.

### Фонетические исправления: отдельный черновик

Удалённый редактор допускает только создание `/phonetic_tags/review_proposal` (existing=false) с точным base.status и base.sound_tokens из существующей карточки, source=editorial_review, status=suggested, usable_for_generation=false, sound_tokens, stress_syllable, syllable_count, stressed_vowel и reason. Валидатор проверяет допустимые фонемы (без V), гласные, номер ударного слога, ударную гласную и неизменность исходного состояния. Буквенно-звуковое соответствие диагностируется существующим sound-index без допуска к автоматизации. Предложение хранится отдельно, не заменяет старый машинный или редакторский анализ и не меняет архив. Индекс помечает наличие предложения. Пилот — одиночные русские слова; обновление действующего разбора, повторное редактирование предложения и изменение статусов требуют отдельного утверждённого механизма, учитывающего новую слоговую классификацию. CI проверяет реконструкцию кандидата и совпадение игровых выгрузок с исходником; проба слова кот не является методическим изменением.

### Типизированные семантические предложения

`semantic_operations` в удалённом редакторском пакете — список объектов type, subject, object, reason. Каждый участник — точный снимок {id,lemma,meaning}, null для отсутствующего значения; обе карточки должны быть словами и не алиасами. Используется существующий список типов semantic-review, симметричные пары и has_part/part_of нормализуются, проверяются существующие связи и открытые предложения, новые циклы is_a и part_of, часть речи для синонимов/антонимов/противопоставлений, признак обобщающего понятия для is_a. Предложения хранятся в semantic_review_proposals исходной карточки в семантическом модуле, отдельно от действующих relations. Статус suggested, usable_for_generation=false; импорт внешних лицензированных источников и утверждение/удаление связей пока не допускаются этим маршрутом. Очередь semantic-proposals показывает оба конца ожидающих проверки связей. CI проверяет реконструкцию пакета, равенство активного графа и очередь. Тестовая связь не редакторское решение.

### Решения по предложениям

`review_decisions` — отдельный запрос на уже существующие предложения (operations=[]), с точным SHA предложения, ID владельца, действием и обоснованием. Семантическое принятие независимой редакторской пары требует sense_checked, typical_for_children, independently_authored=true. Проверяются текущие значения, дубли, циклы; новая связь добавляется без изменения прежних. Игровой валидатор допускает новую ревизию только при совпадении записи решения, хэша предложения и точных ID связи. История `editorial_decision_history` сохраняет исходное предложение и решение; отклонение убирает его из очереди, но не из истории. Не заявляется подтверждение человеком: human_reviewed=false, доверенный редакторский запрос не является аутентификацией методической проверки. Фонетическое отклонение поддерживается, активация пока заблокирована до согласования производных полей и слоговой классификации. Отдельная очередь phonetic-proposals показывает такие предложения. Внешние источники не поддерживаются этим маршрутом. CI проверяет принятие и отклонение на временном кандидате; это не изменение живой библиотеки.

Режим не включается автоматически; действующий UI, main и визуальная ветка не изменяются. Проверяется имитацией GitHub и реальным inspect через общий request runner. ### Безопасное применение пакета к новой генерации

`node scripts/library-apply-bundle.cjs SOURCE_DIR BUNDLE_DIR NEW_DIR EXPECTED_PREVIEW_SHA256` требует контрольную сумму из независимо просмотренного preview (не брать её из самого пакета). Проверяет точную исходную генерацию, статус, воспроизводит все ограниченные операции и решения, сверяет отчёт, манифест, точный набор файлов и байты каждого изменённого модуля с результатом воспроизведения. Отклоняет неизвестные файлы, симлинки, повреждения, конфликт источника и уже существующий каталог. Не копирует непроверенное содержимое: создаёт заново рассчитанную генерацию, прогоняет полный валидатор и архивную проверку, затем атомарно переносит в отдельный новый каталог. Статус staged_generation_validated_not_activated: это не переключение канонического источника и не публикация. CI применяет весовой пакет, семантическое предложение и последующее решение; отдельно проверяет отказ устаревшего и повреждённого пакета. Пробные данные не предназначены для утверждения.

### Клиентский контроллер веб-редактора

Добавлен независимый от DOM `public/editor/modular-client.mjs` и тесты транспорта. Поддержка небольших поисковых/inspect запросов, фиксация версии, формирование операции из точного значения, явный preview/candidate, проверка билета, SHA запроса и результата, обработка отсутствующего результата и конфликтов. `app.js`, HTML и CSS не тронуты; это подготовленный модуль логики, не законченный интерфейс. Отказ от ожидания локальный; нет автоматической публикации или переключения. Перед подключением UI необходимо устранить задержку запуска Actions для каждого поиска (кэш/серверный индекс) и предусмотреть хранение билетов/черновиков. Тесты используют имитацию API, не реальный OAuth.

### Быстрое серверное чтение

`editor-service/modular-read-cache.mjs` и `/api/modular/read` обеспечивают поиск SQLite и точечное чтение без Actions на каждый запрос. Один кэшированный снимок и индекс, перепроверка HEAD через 15 секунд, проверка Git blob, отказ при устаревшем SHA или сбое обновления. Слоговые типы недоступны до актуальной разметки. Контроллер `cachedQuery` не требует билета, но проверяет SHA запроса и источник. UI, публикация и основной источник не переключены. Docker включает только необходимые скрипты. CI сравнивает кэшированный результат с удалённым протоколом.
