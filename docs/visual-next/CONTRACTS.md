# Контракты замены

## Границы модулей

`src/visual` — самостоятельная визуальная реализация. Корневой `index.css` объявляет слои reset → foundation → primitives → compositions → games → motion. Файл темы переводит существующие themeVars в CSS-переменные, не копирует художественный реестр. Стенд импортирует только новый корневой CSS. До приёмки ни один текущий игровой импорт не переключается.

Компоненты получают содержимое через типизированные props. Визуальный слой не импортирует библиотеку, подбор материала и правила игр. Игра управляет состоянием; компонент сообщает о действии callback-ом. Не используются Children/cloneElement, селекторы по тексту и условия theme/game в примитивах.

## Оболочка настроек

SettingsLayout принимает title, headerActions, leading, primary, secondary, appearance, footer, supplementary. Порядок колонок задаёт вызывающая игра. Например, конвейер передаёт учебную задачу в primary, правила в secondary; оболочка не знает о конвейере. Сохранение материала остаётся у существующего адаптера MaterialPresetContext.

На широком экране — две равные колонки и независимая область оформления. На узком — одна прокручиваемая колонка, оформление раскрывается отдельно. Футер не входит в прокручиваемую область. Высота ограничена viewport, внутренние flex/grid дети имеют min-size:0. Ни одно поле не позиционируется по порядковому номеру ребёнка.

## Игровая оболочка

GameLayout принимает navigation, status, fullscreen, scene, board, overlay. Toolbar принимает pause, sound, hint, task, counters, fullscreen. Три навигационных действия занимают одинаковые места на всех ширинах. Размер кнопок — 60% высоты шапки. Центрирование и адаптивная геометрия принадлежат Toolbar, а не играм.

GameDialog принимает title, description, award, actions. DialogActions получает явные обработчики settings, home, continue/repeat. Компонент не выбирает обработчик по наличию русского aria-label. Диалог ограничен по ширине и высоте, при недостатке места прокручивается содержимое.

## Примитивы

- Button: tone, disabled, pressed, type; все состояния берутся из общего набора скинов.
- IconButton: обязательное доступное имя, icon, pressed, disabled. Существующий Icon остаётся единственным набором пиктограмм.
- Surface: panel/card/field. Panel воспроизводит текущую объёмную рамку из существующих токенов поверхностей; card — цельное изображение с сохранением прозрачных углов. Nine-slice применяется только там, где его использование подтверждено эталоном.
- Field/Select/Disclosure: видимая подпись и корректная связь label/id; нативное управление клавиатурой.
- Choice: checkbox/radio/switch; настоящие input, без подмены состояния нарисованной галочкой.
- Quantity: один источник value; number/range/stepper синхронны, возможны дискретные stops.
- Card/Artwork: aspect, содержимое, состояние; contain для предметов, фоновые сцены cover, подписи не влияют на пропорции арта.

## Принятие замены

Каждый компонент имеет собственный CSS-файл и демонстрацию состояний в трёх темах. После интеграции в игру сравниваются реальные геометрия и снимки, а не только стенд. Старые правила удаляются одновременно с окончательным переключением всех потребителей соответствующего компонента. Параллельный стенд допустим на этапе разработки, параллельные каскады в одном игровом документе — нет.

Отдельные исправления известных дефектов маркируются в отчёте. Случайное расхождение не становится новым эталоном автоматически.

## Переходники реальных экранов · 24 ноября 2026

SettingsLayout и Toolbar используются как стендом, так и действующими игровыми адаптерами. Только адаптер передаёт таблицу прежних CSS-классов; новый компонент не содержит селекторов или условий по игре. heading и overlay — явные области содержимого, contentAs сохраняет семантику существующего экрана. Таблицы совместимости удаляются после переключения потребителей на новые стили.

DialogActions и DialogContent общие для обоих способов открытия окон. Открытие native dialog, прежняя overlay-оболочка и игровое состояние принадлежат вызывающему адаптеру. Компонент действий получает конкретный continue/repeat callback; переход домой использует href либо явно переданный onHome.
