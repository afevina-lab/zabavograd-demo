## Уточнение воспроизводимости игровых кадров (captureVersion 2)

Первое расширенное сравнение подтвердило совпадение всех настроек/раскрытых панелей, но выявило 21 нестабильный игровой кадр в нейтральной теме: разное положение движущегося конвейера, таймеры и промежуточные кадры появления/результата. Глобальное animation:none не перекрывало более специфичные старые !important; снимок результата мог оставаться в промежуточной прозрачности. Это ограничение первоначальной съёмки, а не основание принимать другой внешний вид.

В свежих страницах CI используется управляемый clock для interval/RAF, один и тот же seed и явное продвижение на секунду после запуска. Конечные кадры finite CSS/WAAPI animations устанавливаются через Animation.finish(), бесконечные приостанавливаются в одинаковом времени. Пауза/результат обязаны быть непрозрачными при съёмке. Изменение относится только к окружению сравнительных снимков; полные функциональные проверки остаются на настоящих часах. Код main-эталона 953797f и допуск 0,1%/16 не изменялись, скрывающих масок нет. Оба набора заново снимаются из разных исходников в одинаковом окружении; изображения не копируются друг из друга. Добавлены три теста управляемых часов.

captureVersion 3 фиксирует предусмотренный самим приложением prefers-reduced-motion: reduce для статического pixel-diff и ожидает декодирования картинок. После фиксации времени оставались три небольших forest-расхождения по краям декоративных деревьев; размеры/содержимое настроек и игровые элементы совпадали. В обоих исходниках используется один и тот же режим; ассеты и допуск не меняются, элементы не скрываются. Для оставшихся infinite-анимаций дополнительно ожидается animation.ready после pause. Полные функциональные сценарии по-прежнему выполняются отдельно без reduced-motion и без подмены часов. Pixel-diff подтверждает устойчивые состояния, не является проверкой совпадения всех промежуточных анимационных кадров.

captureVersion 4 дополнительно загружает те же Akt.ttf/Londrina.ttf перед первым запуском приложения (только тестовая HTML-загрузка), чтобы ResizeObserver не сохранял размеры промежуточного шрифта. Сам JS/CSS приложения не переписывается. Снимок принимается после секунды неизменного изображения, иначе проверка ожидает стабилизации или падает через 6 секунд; так в эталон не попадает затухающая внешняя полоса прокрутки. Это ожидание, не маска и не скрытие. Добавлены четыре теста готовности шрифтов/кадра; всего 209 Node-тестов и 5 тестов pixel-diff.
