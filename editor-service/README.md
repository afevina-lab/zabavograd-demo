# Веб-редактор библиотеки

Страница: https://afevina-lab.github.io/zabavograd-demo/editor/

Редактор читает актуальный `outputs/library-v2.json` из main. Не изменяет собранный library.json самостоятельно. Есть поиск, ветки, семь сортировок с направлением, просмотр всех полей, формы редактирования, добавление значений и веток, назначение существующих связей, экспорт/импорт черновика. Новые связи и машинные кандидаты не утверждаются автоматически.

## Однократное подключение входа и анализа

GitHub Pages не исполняет сервер. Разместите сервис из `editor-service/Dockerfile` на хостинге Docker с HTTPS. Например, в Render создайте Web Service из этого репозитория, выберите Docker, путь Dockerfile `editor-service/Dockerfile`, контекст `.`. Стоимость и условия выбранного тарифа проверяйте до создания. Пример настроек: `editor-service/render.yaml`.

1. После получения адреса сервера откройте https://github.com/settings/applications/new . Название: «Забавоград — редактор». Homepage URL: https://afevina-lab.github.io/zabavograd-demo/editor/ . Callback URL: `https://АДРЕС-СЕРВЕРА/auth/callback`.
2. В настройках сервера задайте `SERVICE_URL` (HTTPS-адрес без конечного /), `GITHUB_CLIENT_ID` и секрет `GITHUB_CLIENT_SECRET`. Секрет вводите только в защищённое поле хостинга, не в чат и не в Git.
3. Укажите адрес сервера в разделе «Подключение» редактора. Нажмите «Войти через GitHub». Разрешение public_repo используется только для указанного публичного репозитория; сервер проверяет права записи. Доступ действует час, токен GitHub остаётся на сервере в памяти. После перезапуска требуется новый вход.
4. Сохранение создаёт отдельную ветку и pull request. После проверки примите изменения на GitHub. Публикация производится существующим workflow; успешный PR не означает успешную публикацию.

Анализатор: pymorphy3 (MIT), словарь OpenCorpora; результаты сохраняются с указанием источника, только как suggested и unusable for generation. Автоматического определения смысловых связей и подтверждения фонетики нет. За один запрос — до 50 слов. Нужна авторизация.

## Проверки и ограничения

`node --test editor-service/model.test.mjs`. Docker запускает Node 24 и Python с pymorphy3 2.0.6. Реальный OAuth-вход, создание PR и серверный анализ требуют размещённого сервера и настроенных секретов; до этого доступны чтение, редактирование и скачивание черновика.

Существующие проверки проекта содержат исторически фиксированные количества и значения. Редакторские правки, затрагивающие такие условия, могут потребовать обновления соответствующего контрольного сценария в PR; редактор не отключает эти проверки. Архив legacy_source не предназначен для ручного исправления; менять его не нужно.

Несохранённые правки находятся в памяти вкладки. Перед закрытием скачайте черновик. При изменении main сохранение блокируется до сверки. Нельзя удалять существующие ID. JSON позволяет править сложные структуры; обычные поля доступны без него.

## Экспериментальный модульный API (не включён на действующем сайте)

Сервер в интеграционной ветке поддерживает `EDITOR_MODULAR_REHEARSAL=1`. Только при явном включении после прежней авторизации доступны GET `/api/modular/info`, POST `/api/modular/query`, POST `/api/modular/edit`, GET `/api/modular/result?ticket=...`. Query принимает существующие ограниченные запросы version=1, mode=query, command=sqlite/find/inspect/select/gaps/inventory. Edit принимает протокол preview/candidate с точными SHA и ограниченными операциями. POST возвращает HTTP 202 и ticket, не подтверждение выполнения. GET result читает небольшой отчёт; result_not_available означает лишь отсутствие результата, не гарантирует выполнение. Старые /api/library и /api/save в экспериментальном режиме блокируются, чтобы не перепутать основной и тестовый источники. При выключенном флаге прежнее поведение сохранено. Сервер отправляет только файл запроса в отдельную ветку; Actions проверяет и создаёт отдельный отчёт/кандидат. Не создаёт PR, не меняет main, не публикует сайт. Проверки серверного адаптера используют имитацию GitHub, реальный OAuth и хостинг не проверены. Клиент public/editor не изменялся: требуется отдельная адаптация интерфейса, а также переключение источника после завершения визуальной ветки.

### Клиентский контроллер (без изменения интерфейса)

`public/editor/modular-client.mjs` — браузерный контроллер `createModularClient(api)`; использует имеющийся авторизованный транспорт. `query`/`inspect` возвращают билет; `collect(ticket)` явно запрашивает результат. Проверяет полную SHA коммита запроса, SHA его JSON и источник результата; последующие запросы привязаны к источнику. `operation` формирует точное ожидаемое старое значение из последнего inspect для трёх разрешённых полей. `requestPreview`, затем отдельный `requestCandidate(preview_sha256)` подготавливают кандидат без изменения источника. `abandon` прекращает локальное ожидание, но не отменяет Actions. `query(...,true)` начинает новый поиск после завершения/отмены ожидающих запросов. Состояние только в памяти; UI обязан сохранять билеты/черновики при необходимости. Клиент не подключён к app.js, не публикуется, не вызывает старые API. Каждый запрос пока запускает GitHub Actions — это безопасная репетиция, а не мгновенный production-поиск; для интерактивного редактора понадобится кэш актуального индекса на сервере или отдельный read-only сервис.

### Кэш чтения (эксперимент)

POST `/api/modular/read` после прежней авторизации возвращает `cached_result` сразу, без ветки запроса/Actions. Кэш держит один снимок в памяти и один временный SQLite, повторно проверяет HEAD интеграции через 15 секунд (не заявляет мгновенную актуальность), объединяет одновременные обновления. При смене HEAD скачивает зафиксированный Git blob, проверяет размер и SHA-1, пересчитывает логический SHA-256, совпадающий с модульным источником; если содержимое прежнее, индекс сохраняется. При ошибке обновления старый снимок не выдаётся. Запросы ограничены 40 строками и 96 КиБ; full запрещён; слоговая разметка намеренно не доступна в этом кэше до согласованного источника. Клиент `cachedQuery` проверяет ответ и фиксирует источник. Только чтение; редактирование остаётся через Actions. Тесты используют имитацию GitHub и реальную библиотеку CI; хостинг и сеть реального OAuth не проверены. По-прежнему экспериментальный снимок, не live main. Старый UI не подключён.

### Пилот интерфейса

Открыть `/editor/?modular=1` на проверочной сборке и подключить HTTPS-сервер с `EDITOR_MODULAR_REHEARSAL=1`. Переключатель сохраняется в sessionStorage этой вкладки через OAuth; `?modular=0` возвращает старый режим. В пилоте доступны поиск, категории, типы, карточки с ограниченными полями, редактирование веса и двухэтапная подготовка кандидата. Результат проверяется кнопкой вручную, можно сбросить локальное ожидание и скачать черновик. Нельзя загружать полный V2 из модульного режима. Пилот не является опубликованным редактором; проверка реальной авторизации и восстановление черновиков остаются отдельными этапами.

Серверный кэш поддерживает также будущую каноническую модульную генерацию: читает политику источника и проверяет все blobs, manifest и логический SHA общей функцией store.loadFiles. Неизменившиеся blobs повторно не скачиваются. До переключения источник остаётся интеграционной веткой. Холодный старт и реальный HTTPS/OAuth требуют отдельной проверки.
