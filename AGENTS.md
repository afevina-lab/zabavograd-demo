# Правила проекта «Забавоград» · единый публичный репозиторий

**Единственный исходник:** `afevina-lab/zabavograd-demo/main`; `gh-pages` — собранная публикация. Старый приватный `afevina-lab/zabavograd` не является источником для дальнейшей разработки и служит временной страховочной копией.

Перед изменениями читать `outputs/PROJECT.md` и последние подтверждённые решения `outputs/DECISIONS.md`; для игр — `outputs/GAMES.md`, для библиотеки — `outputs/LIBRARY_EDITOR.md`, изображений — `outputs/ASSETS.md`, оформления — `outputs/VISUAL_SYSTEM.md`. Поздние решения приоритетнее исторических. Отвечать пользователю по-русски, конкретно.

- Только `outputs/library-v2.json` редактируемый источник словарных данных. `library.json`, `semantic-graph.json`, `public/grammar-frames.json` и `outputs/Библиотека.html` — производные. Не редактировать независимо.
- ID, значения, категории, веса, формы, фонетика, двусторонние связи, семьи животных и привязки изображений должны сохраняться при миграции. Разные слова/значения с одинаковым написанием не склеивать без проверки.
- Отделять статус `suggested` от `verified`; 55 неутверждённых моделей действия не передавать генератору. Внешние лингвистические источники использовать для проверки, с учётом лицензий; во время игры всё статично и офлайн.
- Не придумывать связи слов, утверждённость фонетического разбора или грамматические формы. Не создавать автоматические ссылки для спорных рисунков. На Git только сжатый WebP; исходные PNG сохраняются локально.
- Не публиковать данные детей, личные пути к исходникам, ключи или сторонние материалы без прав на публикацию.
- Жизни списывает только педагог, с отменой. Завершение игры не является доказательством освоения навыка.
- UI темы только в `src/design-system/themes.ts`, анимации — в `motion.ts` и `motion.css`. Не дописывать специальные темы прямо в компонентах.
- Проверки перед публикацией: `npm test`, `npm run check:library`, `npm run check:design-system`, `npm run build`, проверка автономного выпуска и визуальный smoke-тест на разных размерах.
- Публикация считается завершённой только после успешного GitHub Actions и проверки файла в `gh-pages`. Не считать Pull Request или запись в `main` публикацией сайта.
